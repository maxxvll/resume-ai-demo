系统架构

实时连接负责及时通知，数据库保存最终状态，对象存储承载文件内容。

  1. 多端客户端

    Vue 3 与 Tauri 2，覆盖桌面端、移动端和浏览器调试。

  2. 通信边界

    REST 处理业务请求，WebSocket 推送通知，SSE 输出 AI 回复。

  3. Java 业务服务

    管理账号关系、会话消息、文件分享和 AI 会话。

  4. 数据与事件

    MySQL、Redis、Kafka 与 MinIO 分别承载状态、事件和文件。

音视频：服务端完成身份校验和信令转发，媒体尽量由终端通过 WebRTC 直接传输。

离线恢复：在线连接用于提醒，最终恢复依赖持久事件、设备游标和幂等合并。

关键工程设计

技术选择围绕真实业务问题展开，每项设计都有明确的系统结果。

消息重复与断线恢复

客户端为一次发送保留稳定消息号，服务端先幂等落库，再异步投递。在线设备通过 WebSocket 收到提醒，断线设备按持久事件和游标补拉。

结果：弱网重试不会重复入库，换端或重连后仍可恢复未消费事件。

文件对象与业务状态

MySQL 保存文件元数据、容量和引用关系，MinIO 保存对象内容。聊天文件与云盘文件采用不同访问入口，上传或转存失败时执行补偿清理。

结果：支持聊天文件转存和受控分享，并降低孤儿对象、错误鉴权和重复存储风险。

AI 上下文与多端同步

客户端从本地消息、收藏和联系人中筛选少量相关上下文，服务端校验会话并通过 SSE 返回增量内容，完成后持久化正式消息。

结果：减少无关聊天数据进入模型，保持流式体验，并让正式回复同步到其他设备。
